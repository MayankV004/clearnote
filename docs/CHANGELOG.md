### Phase A: Design System Foundation & Component Gallery
- **Clinical Design Principles (`docs/DESIGN_PRINCIPLES.md`)**: Formulated the "Quiet Confidence" design doctrine, anti-"AI slop" enforcement matrix (banning purple/pink gradient backgrounds, generic 32px bubble cards, and magic-wand emojis), and strict 2-zone animation policy.
- **Design Tokens & Theme Foundation (`frontend/src/app/globals.css`)**: Established cool slate neutral scale (`Slate-50` to `Slate-950`) paired with a single clinical teal accent (`#0D9488` / `#14B8A6`) and strict status colors. Verified WCAG 2.2 AA / AAA contrast (>14.8:1 text contrast) across both light and dark themes. Added systematic spacing (4/8px), radii (4/6/8/12px), elevation shadows, z-index scale, and global `prefers-reduced-motion` zero-transform enforcement.
- **Typography Integration (`frontend/src/app/layout.tsx`)**: Replaced deprecated Google fonts Figtree/Noto Sans with self-hosted `Geist Sans` (for UI typography) and `Geist Mono` (for tabular numerals, dosages, ICD-10 codes, and millisecond timestamps).
- **Core Clinical Component Library (`frontend/src/components/ui/`)**: Built and standardized `Button`, `IconButton`, `Input`, `Textarea`, `Select`, `Checkbox`, `Switch`, `Badge`, `Banner`, `Dialog`, `Drawer`, `ConfirmDialog`, `Tabs`, `Table` (with sortable columns, dense mode, and responsive mobile stacked card patterns), `Avatar`, `Tooltip`, `Skeleton`, `EmptyState`, `ErrorState`, and `PermissionDenied`.
- **Clinical AI Trust & Governance Components (`frontend/src/components/clinical/`)**: Implemented `<AIContentBlock />` with explicit provenance states (`[AI Draft]` vs `[Clinician Verified]`), `<CitationChip />` with retrieval similarity tags, `<ConfidenceIndicator />` with low-evidence warnings, `<ReviewStatusBar />` for gated clinical sign-off, `<DiffView />` with side-by-side and inline token audits, and `<StreamingText />` with a calm clinical cursor.
- **Motion Primitives (`frontend/src/components/motion/`)**: Added `<Reveal>`, `<FadeStagger>`, `<AnimatedNumber>`, and `<PageTransition>` powered by lightweight `motion`, operating on transform/opacity only with automatic reduced-motion degradation.
- **Living Component Gallery (`/dev/components`)**: Created interactive route displaying every component in every state (default, hover, loading, error, disabled), with live light/dark theme toggles and dialog/drawer simulators. Captured full-page desktop and mobile screenshots in `docs/screenshots/ui/dev-components/`.

### Data & Reliability
- **TICKET-09B (`REL-01` / `DATA-04`)**: Added background task idempotency guards in `consultation_service.py:_run_transcription`, preventing duplicate processing jobs from executing concurrently or corrupting notes already in `PROCESSING`, `AWAITING_REVIEW`, or `COMPLETE`. Upgraded `GET /health` into a deep probe testing live database connectivity with degraded status signaling. Added metadata `source_filter` filtering and `reindex_guidelines` batch recomputation to `RAGService`. Eliminated N+1 queries in consultation queries by standardizing `selectinload` across `soap_note`, `medications`, `diagnoses`, and `interactions`.
- **TICKET-11 (`REL-03`)**: Standardized all Boto3 S3 client calls onto Python 3.12 `asyncio.to_thread` across `upload_audio`, `upload_pdf`, `upload_signature`, `download_audio`, `delete_object`, and `generate_presigned_url`. Eliminates framework coupling and guarantees non-blocking execution on the main ASGI event loop.
- **TICKET-10 (`REL-02`)**: Replaced unbounded in-memory `bytearray` accumulation in `/consultations/{id}/stream` WebSocket with `tempfile.SpooledTemporaryFile(max_size=5MB)`. Audio chunks stream to disk once resident memory exceeds 5MB, preventing process heap exhaustion and out-of-memory container crashes during prolonged (30+ minute) consultations.
- **TICKET-07 (`DATA-03`)**: Implemented S3 asset cascade deletion in `process_data_deletion`. When a patient right-to-erasure request is processed, all associated consultation audio recordings (`audio_s3_key`) and prescription PDFs (`prescription_s3_key`) are purged from AWS S3 storage prior to deleting database records, eliminating orphaned PHI in cloud object stores.
- **TICKET-05 (`DATA-01`)**: Added Alembic migration `e2f3a4b5c6d7` creating an HNSW vector index (`idx_guideline_chunks_embedding_hnsw`) on `guideline_chunks.embedding` using `vector_cosine_ops` (`m=16`, `ef_construction=64`). Replaces $O(N)$ sequential table scans during RAG interaction checks with sub-millisecond approximate nearest neighbor index traversal.

### AI Safety & Quality
- **TICKET-18 (`AI-05`)**: Added automated clinical golden benchmark evaluation suite (`backend/tests/evals/golden_dataset.py`, `backend/tests/evals/test_clinical_evals.py`). Features 3 comprehensive annotated clinical vignettes covering acute pharyngitis with penicillin anaphylaxis, essential hypertension with knee osteoarthritis polypharmacy, and type 2 diabetes with stage 4 CKD lactic acidosis contraindications. Computes precision, recall, and F1 scores across medications, ICD-10 diagnoses, and patient allergies, enforcing strict regression bounds (medication recall >= 95%, ICD-10 recall >= 90%, allergy recall = 100%).
- **TICKET-14B (`AI-03` / `AI-04`)**: Added grounding citations, low-evidence confidence capping, and automated model failure fallbacks in `RAGService` and `LLMService`. Configured primary LLM model `llama-3.3-70b-versatile` with automated fallback to `llama-3.1-8b-instant`. In drug interaction RAG, when local guideline retrieval yields zero chunks, output confidence is strictly capped to `<= 0.5` and annotated as `"(Unverified in local guidelines)"`. On LLM network or 5xx exceptions, safety caution alerts with `confidence=0.0` and `severity="MODERATE"` are recorded to require clinician manual verification in clinical formularies rather than silently failing.
- **TICKET-08 (`DATA-02`)**: Upgraded guideline PDF chunking to semantic `RecursiveCharacterTextSplitter` with clinical delimiters (`["\n## ", "\n### ", "\n\n", "\n- ", "\n", ". ", "; ", " ", ""]`), chunk size 800, and overlap 150. Preserves clinical headings, indication/contraindication bullet points, and dosage tables across chunk boundaries.
- **TICKET-06 (`AI-01`)**: Implemented human-in-the-loop review state machine. Consultation status now transitions to `AWAITING_REVIEW` upon background extraction completion. Added `POST /consultations/{id}/approve` clinical sign-off endpoint. Blocked prescription generation until explicit doctor approval is recorded, preventing unreviewed AI hallucinations from reaching patients. Added Alembic migration `c1a2b3d4e5f6` for `consultationstatus` enum.

### Security
- **TICKET-01E (`SEC-08`)**: Calibrated Content-Security-Policy (CSP) header in `SecurityHeadersMiddleware` to explicitly whitelist Clerk authentication domains, S3 presigned asset delivery, and Deepgram WebSocket endpoints. Applied SlowAPI rate limiting to public prescription endpoints (10/min), guideline PDF ingestion (5/min), and patient data deletion requests (10/min).
- **TICKET-01D (`SEC-07`)**: Implemented prompt injection defenses with structural XML tag delimiters (`<untrusted_clinical_dialogue>`, `<guideline_context>`, `<patient_context>`) in `soap_extraction.py` and `drug_interaction.py`. Added explicit system instructions to ignore meta-commands and treat dialogue strictly as untrusted clinical data.
- **TICKET-01C (`SEC-06`)**: Implemented HIPAA PHI sanitization in application logging (`mask_email`, `mask_phone`). Removed plaintext patient names, email addresses, and phone numbers from logs across `patient_service`, `notification_service`, and `webhooks`.
- **TICKET-01B (`SEC-03`)**: Implemented `set_rls_doctor_id` parameter hook in `get_current_doctor` (covering both cache hits and misses) and `get_current_doctor_ws`, executing parameterized `set_config('app.current_doctor_id', :doctor_id, true)` to enforce PostgreSQL Row-Level Security at the database layer.
- **TICKET-04 (`SEC-05`)**: Replaced naked UUID lookup on `GET /consultations/public/{id}/prescription` with HMAC-SHA256 signed access tokens with 7-day expiration, mitigating UUID enumeration attacks and securing public prescription sharing.
- **TICKET-03 (`SEC-04`)**: Enforced tenant isolation in `POST /data-deletion/`, `POST /data-deletion/{id}/process`, and `GET /data-deletion/`. Doctors can now only request, process, or view data deletion records for their own verified patients.
- **TICKET-02 (`SEC-02`)**: Populated `request.state.user_id` in `get_current_user` and `get_current_doctor` dependencies, ensuring `RequestLoggingMiddleware` correctly records all mutating API interactions into the `audit_logs` table for HIPAA compliance.
- **TICKET-01 (`SEC-01`)**: Authenticated consultation audio WebSocket stream (`/{consultation_id}/stream`) with Clerk JWT verification and consultation ownership validation. Unauthorized connections are terminated with code 1008.
